# Lap Time Tracking

3 人 1 組の駅伝（リレー）大会のラップ計測システムです。
PHP + SQLite で動作し、外部ライブラリは不要です（Composer 不要）。

- **計測端末**（スマートフォン）: ビブ番号を 2 桁で入力すると、その瞬間の通過時刻を記録
- **管理画面**（Web）: 大会・選手の登録、リアルタイム集計、複数端末の突き合わせ、Excel 出力

```
├── config.php            設定（上書きは config.local.php）
├── data/                 SQLite DB（自動生成・Web 非公開）
├── public/               ← ドキュメントルート
│   ├── index.php         入口（計測端末 / 管理画面へのリンク）
│   ├── admin/            管理画面
│   ├── api/index.php     JSON API
│   ├── m/                計測端末アプリ（PWA）
│   └── assets/           管理画面の CSS / JS
├── src/                  PHP クラス・スキーマ
└── tests/run.php         テスト（php tests/run.php）
```

## 動作環境・セットアップ

- PHP 8.0 以上（拡張: `pdo_sqlite`, `mbstring`, `zip`）
- Web サーバ（Apache / nginx など）。ドキュメントルートを `public/` に設定してください。
  - ドキュメントルートを変更できないレンタルサーバでは、同梱のルート `.htaccess` が `public/` へ振り分け、`src/` `data/` への直接アクセスを拒否します。
- `data/` ディレクトリに Web サーバの書き込み権限が必要です（初回アクセス時に DB が自動作成されます）。

```bash
# 管理者パスワードの設定（必須）
cat > config.local.php <<'EOF'
<?php return ['admin_password' => '強いパスワードに変更'];
EOF

# 動作確認用の簡易サーバ
php -S 0.0.0.0:8000 -t public
# → 管理画面 http://<サーバ>:8000/admin/   計測端末 http://<サーバ>:8000/m/
```

> **HTTPS を推奨します。** 計測端末のオフライン起動（Service Worker）は HTTPS でのみ有効です。
> HTTP でも記録・同期・オフライン保存は動作しますが、圏外でページを再読み込みすると画面が開けません。

### 管理者アカウント

- ユーザ名 `admin`、パスワードは `config.php`（`config.local.php`）の `admin_password` で固定です。
- ログイン時に `users` テーブルへ同期されます。将来の複数ユーザ管理は `users` テーブルにユーザを追加する形で拡張できます（`role` 列あり）。

## 当日の運用

1. **管理画面** で大会を作成（試合名・日程・場所）。
2. **選手登録** タブで名簿を取り込み（Excel の表をコピー＆貼り付け、または CSV）。
3. 計測係のスマートフォンで `/m/` を開き、大会を選択（初回は端末名を入力）。
   選手情報は端末に読み込まれ、以降はオフラインでも表示できます。
4. 号砲と同時に、いずれかの端末で **「計測スタート」**。
   最初に押された時点の **サーバ時刻** がスタートになり、他の端末はその時刻を共有します（管理画面で修正可）。
5. 走者がラインを通過したらビブ番号を 2 桁で入力（`05` のようにゼロ埋め）。**1 桁目を押した瞬間** が通過時刻です。
   - テンキー / テキストボックス（OS のキーボード）/ 物理キーボードのいずれでも入力可。1 桁 + Enter は 0 埋め。
   - 1 桁目から 10 秒以上 2 桁目が無い場合は誤記録防止のため取り消されます。
   - 直前の記録は画面に表示され「取消」で削除できます。**履歴** タブで全記録の確認・削除・復元ができます。
6. 管理画面の **速報・集計** タブで、全端末の記録を突き合わせた結果がリアルタイム（3 秒ごと）に表示されます。
   黄色のセルは確認が必要な通過です。クリックすると端末ごとの時刻を比較し、除外や正しい時刻の確定ができます。
7. **Excel 出力** で成績表をダウンロード。

### 計測パスコード（任意）

大会設定で「計測パスコード」を設定すると、計測端末は API 利用時にパスコードが必要になります。
会場の Wi-Fi など第三者がアクセスできる環境では設定を推奨します。

## 競技ルールの扱い

| 項目 | 実装 |
| --- | --- |
| チーム | ビブ番号（00〜99）で管理。1 チーム 1 ビブ |
| ラップ | 同じビブの n 回目の通過 = n 走のゴール。ラップ = 前の通過（1 走はスタート）からの差 |
| チーム記録 | 登録人数分の通過が揃った時点の「最終通過 − スタート」 |
| 正式 / オープン | 登録人数が「正式参加の人数」（既定 3）未満のチーム、または「オープン指定」のチームはオープン参加。**個人のラップ・チーム記録は計測するが順位は付けない** |
| 順位 | 総合順位・区分順位・区間順位（正式参加のみ）。同タイムは同順位 |
| DNS / DNF / DQ | チーム編集で指定。順位対象外 |

## 複数端末によるチェックの仕組み

ミスを防ぐため、複数の端末で同じ走者を同時に記録し、サーバ側で突き合わせます。

1. **時刻合わせ**: 端末はサーバの時刻 API を 5 回呼び、往復遅延が最小のサンプルから「サーバ時刻 − 端末時刻」を求めます（2 分ごとに再測定）。
   通過時刻は「端末時刻 + 差」= **サーバ時刻基準** で記録されるため、端末の時計がずれていても揃います。
   時刻未同期のまま記録したものは、同期後に端末の生時刻から補正して送信します。
2. **同一通過のまとめ**: 同じビブの記録で「同一通過とみなす時間」（既定 10 秒）以内のものを 1 回の通過にまとめます。
3. **採用時刻**: 管理者入力 ＞ 端末の中央値（設定で「最も早い端末」にも変更可）。
4. **自動チェック**（集計画面で黄色表示・Excel の「確認事項」列に出力）
   - 端末間の差が許容差（既定 1 秒）を超えている
   - 稼働中の端末のうち記録していない端末がある（記録漏れ・入力ミスの可能性）
   - 同じ端末で二重入力している（早い方を採用）
   - 登録人数を超える通過がある / 未登録のビブ / スタート前の記録
5. **修正**: 誤った記録は「集計から除外」（元に戻せる）、正しい時刻は「管理者入力」で確定（端末記録より優先）。

### 通信が途絶した場合

- 記録・削除・復元はすべて端末の `localStorage` に即座に保存され、3 秒ごとに未送信分をサーバへ送ります。
- 送信は記録ごとの UUID で冪等に処理されるため、再送しても二重登録になりません。
  削除・復元は端末側の更新時刻が新しいものを採用します。
- オフライン中に「計測スタート」を押した場合は、推定したサーバ時刻を保存し、通信回復後に送信します（その時点でスタート未記録の場合のみ採用）。
- 画面上部のバッジで状態を表示します（同期済 / 未送信 n / オフライン ↑n）。

## データベース構造

`src/schema.sql` 参照。時刻はすべて **サーバ時刻基準の UNIX エポックミリ秒（INTEGER）** で保持します。

```
users ─────────── 管理ユーザ（現状 admin のみ。role で将来拡張）

competitions ──┬─< teams ──< runners
 (大会)        │   (ビブ)     (走順・選手情報)
               ├─< devices     (計測端末: 名前・時刻差・最終通信)
               ├─< passes      (通過記録: 端末で入力された生データ)
               └─< audit_log   (操作ログ)
```

| テーブル | 主な列 |
| --- | --- |
| `competitions` | `name` 試合名, `event_date` 日程, `location` 場所, `team_size` 正式参加の人数, `status` 準備中/開催中/終了, `start_ms` スタート時刻, `start_set_by`, `device_code` 計測パスコード, `merge_window_ms` 同一通過とみなす時間, `tolerance_ms` 端末間の許容差, `adopt_method` 採用方法 |
| `teams` | `competition_id`, `bib`（大会内で一意）, `name`, `category` 区分, `force_open` オープン指定, `status` DNS/DNF/DQ, `note` |
| `runners` | `team_id`, `leg` 走順, `name`, `kana`, `gender`, `age` 学年・年齢, `affiliation` 所属, `note` |
| `devices` | `competition_id`, `device_uuid`, `name`, `clock_offset_ms`, `clock_rtt_ms`, `last_seen_at` |
| `passes` | `uuid`（端末採番・一意）, `competition_id`, `device_uuid`, `source` device/admin, `bib`, `time_ms` 通過時刻, `client_ms` 端末の生時刻, `offset_ms`, `deleted` 端末で削除, `client_updated_ms` 後勝ち判定, `admin_excluded` 管理者が除外 |
| `audit_log` | 誰がいつ何をしたか（スタート設定・除外・名簿取り込み等） |

通過記録は物理削除せず、端末での削除（`deleted`）と管理者の除外（`admin_excluded`）を分けて保持するため、後から経緯を確認できます。
スキーマ変更は `src/Db.php` の `migrate()` に `PRAGMA user_version` で段階的に追加します。

## 選手名簿の取り込み

1 行 = 1 選手。見出し行に **ビブ** と **氏名** が必要です。次の見出しを認識します（表記ゆれ・全角半角は吸収）。

| 項目 | 認識する見出し |
| --- | --- |
| ビブ | ビブ, ビブ番号, ゼッケン, No, 番号 |
| チーム名 | チーム名, チーム |
| 区分 | 区分, 部門, カテゴリ, 種別 |
| オープン | オープン, オープン参加（値があればオープン指定） |
| 走順 | 走順, 区間, 走（省略時は行の順） |
| 氏名 / フリガナ | 氏名, 名前, 選手名 / フリガナ, ふりがな, カナ |
| 性別 / 学年・年齢 / 所属 / 備考 | 性別 / 学年, 年齢 / 所属, 学校 / 備考 |

- ビブ・チーム名が空の行は直前のチームの続きとして扱います（Excel のセル結合をそのまま貼り付け可）。
- タブ区切り（Excel からのコピー）、カンマ区切り、UTF-8 / Shift_JIS に対応。
- 管理画面の「テンプレート (CSV)」からひな形をダウンロードできます。

## Excel 出力

`成績` / `端末比較` / `通過記録` の 3 シートを出力します。

- **成績**: 順位・区分順位・ビブ・チーム名・区分・参加区分・走順・氏名・フリガナ・性別・学年・年齢・所属・備考
  に加え、**所要時間**（個人ラップ）・区間順位・通過記録（累計）・**チーム記録**・状態・確認事項。
  チーム単位の列はセル結合。時間は Excel の時刻値（書式 `[h]:mm:ss.0`）なので並べ替え・計算が可能です。
- **端末比較**: 各通過の採用時刻と、端末ごとの記録時刻・差・確認事項。
- **通過記録**: 全端末の生データ（削除・除外を含む）。

## API

`public/api/index.php?r=<route>`（JSON）。計測端末用ルートはログイン不要（パスコード設定時は `X-Device-Code` ヘッダ）。
管理用ルート（`admin.*`）はログインセッションと `X-CSRF-Token` ヘッダが必要です。詳細は `src/Api.php` の先頭コメント参照。

## テスト

```bash
php tests/run.php
```

名簿取り込み、複数端末の突き合わせ（中央値・最速・二重入力・記録漏れ・管理者入力・除外）、順位付け、Excel 出力を検証します。
